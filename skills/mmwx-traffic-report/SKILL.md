# 流量巡检报告(妙妙屋X)

目标:快速给出可读的流量概览与异常名单。全程只读,安全。

## 能力与授权检查

执行前读取当前连接的完整 `tools/list`（包含分页），核对本流程所需工具及 `inputSchema`。下文参数是兼容提示，以当前 schema 的必填项、类型和枚举为准。工具缺失或返回 403 时说明能力缺口，不猜工具名、不自动升级主控；可独立完成的只读步骤继续进行。复用当前任务已有授权，`confirm: true` 按 schema 传递，不重复索要已有授权。

## 步骤

0. **采集健康度**：当前主控支持 `task_runs` 时核对流量采集任务最近一次成功时间及连续失败；不支持时依据流量响应中的时间戳说明时效未知。缺失或过期的数据不能当作零用量。
1. **总体概览**:`traffic_summary` 取跨服务器聚合用量(已用/限额等)。
2. **用户维度**:`user_list` 取全部用户及其套餐/配额;对关注的用户用 `traffic_user_detail`(传 username)拿明细。
3. **服务器维度**:`server_list` 看各服务器状态;单台明细用 `traffic_server_detail`(传 `server_id`)按 inbound tag / 出站 tag 拆分,定位"谁/哪个入站占了多少"。
4. **(可选)历史曲线**:`traffic_snapshots`(可传 `server_id`、`hours`)看历史流量曲线,用于检测突发流量或异常时段。
5. **转发与多套餐**：支持转发工具时用 `forward_status` 找到链与实际规则 ID，再以 `forward_metrics` 获取明细。先核对当前主控是否已把转发计入总体/用户用量，避免二次相加；链的入口计费与倍率以实际配置为准。支持实例模型时用 `package_assignment_list` 核对全部有效实例，不直接累加已过期或停用配额。
6. **汇总成报告**,建议包含:
   - 总用量 / 总限额、整体使用率。
   - 用量 Top N 用户(名称、已用、限额、使用率)。
   - **风险名单**:使用率 ≥ 80%(临近超额)与 ≥ 100%(已超额)的用户。
   - **服务器 Top N**:占用流量最高的几台机器 + 是否健康(离线/异常)。
   - **异常段**:若有 traffic_snapshots,标注异常时段(明显突起)。
7. **给建议**(不自动执行):如对超额用户提示可 `user_set_limits` 限速或按已核验模型使用 `package_assignment_upsert` / `package_assign` 调套餐——但这些写操作要先征得用户同意再做。

## 注意
- 本技能默认只读,不要在未确认的情况下改用户/套餐。
- 计费流量受套餐 `traffic_mode`(oneway=×1 / twoway=×2)影响,报告里注明口径。
