# 节点测速报告(妙妙屋X)

目标:对选定节点发起测速,汇总下行速度与延迟排名。

## 能力与授权检查

执行前读取当前连接的完整 `tools/list`（包含分页），核对本流程所需工具及 `inputSchema`。下文参数是兼容提示，以当前 schema 的必填项、类型和枚举为准。工具缺失或返回 403 时说明能力缺口，不猜工具名、不自动升级主控；可独立完成的只读步骤继续进行。复用当前任务已有授权，`confirm: true` 按 schema 传递，不重复索要已有授权。

## 步骤

1. **取节点**：用 `node_list` 匹配用户已指定的全部、某服务器或若干节点；目标明确就继续，只有无法确定范围时才询问。
2. **(可选)选测速来源**:测速默认走主控本机;若用户有家用测速端,先用 `speedtest_testers`
   列出测速端及在线状态,再在 `node_speedtest` 传所选的 `tester_id`。
3. **逐个发起并绑定本次测试**：先记录目标节点已有结果的 ID/时间，再调用 `node_speedtest`，记录返回的任务 ID、节点、测速来源和提交时间。不要同时发起全部节点。
4. **有界等待**：按任务 ID 读取 `node_speedtest_results`；若接口无任务 ID，只接受提交之后产生、且相对基线新增并匹配节点与来源的结果。缺少足以关联本次测试的字段时标记“无法确认本次结果”，不得把旧的 `ok/failed` 当成本次完成。
   - 使用服务端给出的任务期限；没有期限时默认每 10 秒读取一次，单节点最多 5 分钟（含忙碌重试）。到期停止该节点轮询，记录任务仍未完成，按已授权范围继续其他节点；不要重复提交仍可能在运行的测试。
   - 只有匹配本次任务的 `ok/failed` 才是终态。`failed: 测速端忙` 可在期限内间隔重试，最多 3 次；每次重新绑定任务。它只表示容量冲突，不作为节点故障。
   - 等待期间至少每分钟报告已完成数量和剩余任务；一次等待不超过 60 秒。

5. **出报告**:按下行速度排序,列出 速度 / 延迟 / 来源 / 时间;区分本次成功、确认失败、忙碌、超时与无法关联；未取得本次结果的节点不参与速度排名。

## 注意
- 测速是 PRO 功能;无许可证时工具会返回 403,据此提示用户。
- 家用测速端最多接纳 4 个在途任务,实际带宽测速一次只执行一个;超出容量会返回
  `failed: 测速端忙`。按上述逐个等待流程可避免占满容量。
- `测速端忙` 只说明调度冲突;重试仍失败时单列为测速未完成,不要计入节点不可用数量。
- 测速本身不改配置,安全;无需 confirm。
