# 节点测速报告(妙妙屋X)

目标:对选定节点发起测速,汇总下行速度与延迟排名。

## 步骤

1. **取节点**:`node_list` 列出节点及 ID;与用户确认测哪些(全部 / 某服务器 / 指定几个)。
2. **(可选)选测速来源**:测速默认走主控本机;若用户有家用测速端,先用 `speedtest_testers`
   列出测速端及在线状态,再在 `node_speedtest` 传所选的 `tester_id`。
3. **逐个发起**:对一个目标节点调 `node_speedtest`,参数 `node_id`(可带 `tester_id`)。测速是**异步**的:工具立即返回,结果稍后落库。不要同时发起全部节点。
4. **等待并取结果**:间隔若干秒调用只读工具
   `node_speedtest_results`,按 `node_id` 找到每个节点最近一次的
   `down_mbps / latency_ms / status`。当 `status` 变为 `ok` 或 `failed` 时停止轮询;
   然后再发起下一个节点,且不无限轮询。若结果为 `failed: 测速端忙`,等待数秒后重试
   当前节点(最多 3 次);这是测速端容量信号,不能据此判定节点故障。
5. **出报告**:按下行速度排序,列出 速度 / 延迟 / 来源 / 时间;标注失败的节点(status=failed)及原因。

## 注意
- 测速是 PRO 功能;无许可证时工具会返回 403,据此提示用户。
- 家用测速端最多接纳 4 个在途任务,实际带宽测速一次只执行一个;超出容量会返回
  `failed: 测速端忙`。按上述逐个等待流程可避免占满容量。
- `测速端忙` 只说明调度冲突;重试仍失败时单列为测速未完成,不要计入节点不可用数量。
- 测速本身不改配置,安全;无需 confirm。
