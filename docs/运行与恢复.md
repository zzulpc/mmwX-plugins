# mmwX-plugins 运行与恢复

本页供恢复时使用。2026-09-09 初次整理仅包含文档；2026-10-01 的构建、测试及 0.2.7 发布结果见[项目状态](项目状态.md)。新设备运行与主控配对仍需单独验收。

## 开发环境

1. 恢复源码和必要本地资料，并单独保全同级私有备份。该备份属于历史档案，不自动覆盖当前 `.git`。
2. 优先使用既有验证基线 Go 1.26.8；两个 `go.mod` 当前要求 Go 1.26。记录实际工具链，不把不同版本的覆盖率直接比较。
3. 根据目标模块的 `go.mod` 与 `go.sum` 恢复依赖；执行 Go 命令前进入对应模块。

```bash
# 分别验证两个独立模块；根目录没有 Go module。
(cd proxyparser && go build ./... && go vet ./... && go test ./... -count=1)
(cd speedtest && go build ./... && go vet ./... && go test ./... -count=1)
```

这些也是后续恢复验证命令；2026-10-01 已在原开发环境使用 Go 1.26.8 执行并通过，不能替代新设备的恢复验收。既有测试不要求真正启动代理内核或访问外网；依赖下载与实际网络测速分别处理。

## 测速端运行恢复

本地源码迁移与已部署测速端恢复是两件事。新设备如果只做开发，不需要重新部署正在运行的测速端。

确需运行新测速端时，按 [speedtest/README.md](../speedtest/README.md)选择受支持的二进制或容器方式，核对版本与摘要，并恢复：

- 主控地址、配对授权、测速端名称；令牌从安全存储取得，不写入文档或命令历史。
- 实际持久数据目录及目标平台权限。
- 当前 Dockerfile/README 规定的代理内核和路径；未确认本地内核时，首次启动可能触发下载。
- 真实主控可达性、配对状态与一个经授权的实际检查；配置存在不等于连接可用。

不要为了恢复而自动运行 `speedtest/scripts/release.sh`。规范仓库、发布标签和包版本的要求继续以根 AGENTS 为准。

## 技能和 MCP

`skills/` 保存的 Markdown 要完整迁移，但主控 MCP 服务和连接器授权不会随文件自动恢复。新设备应先确认连接的主控和工具权限；只读检查通过后再按实际任务执行写操作。

## 恢复验收

- [ ] 两个 Go module、依赖文件、技能、许可证与必要本地资料齐全。
- [ ] 当前源码版本和私有历史备份分别定位，没有相互覆盖。
- [ ] 实际执行对应模块验证后记录结果；只复制源码时不记作测试通过。
- [ ] 若涉及部署，分别验证本地源码、远端制品、目标实际版本与主控连接。
- [ ] 没有在迁移过程中自动推送、打标签或替换在线节点。
