## 数据库与恢复判定

包含 SQLite 时，在停止写入后整体备份，或使用 SQLite 的一致备份机制；有未合并 WAL 时不能只复制主文件。`-wal`/`-shm` 的处理遵循所选备份方式，不手工删除以“修复”状态。本轮读取的项目数据库使用了 WAL 为空时的不可变只读方式，其内容哈希不是未来在线备份的一致性证明。

先核对原始输入、冻结版本、代码和外部依赖，再执行对应恢复验收。文件复制、程序能启动、数值复现、人工批准和目标部署分别记录；本次仅交接文档整理完成，未声明新设备已恢复。

本轮源码更新仍只有原有的两个 Go module，`go.mod`、`go.sum`、内核版本及下载依赖未改动。完整工作副本需要包含新加入的解析器回归测试、`substore/egern_yaml.go`、`substore/wireguard_fields.go`、`substore/policy_prune.go`、`speedtest/lifecycle_regression_test.go`，以及：

Python 解释器缓存已加入忽略规则。上述新文件尚未提交，迁移不能只导出 HEAD；应同时携带本次未提交修改和未跟踪文件。2026-09-09 表中的数量与哈希是历史盘点值，不能用于断言本轮修改后文件完全一致。状态和测试边界见[项目状态](项目状态.md)。
